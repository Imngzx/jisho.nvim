1. Introduction                                         *jisho-introduction*

jisho.nvim looks up Japanese words on Jisho.org without blocking the editor
and shows the results as Markdown in a floating window.

Requires Neovim 0.13+ (|vim.async|, |vim.net.request|). `curl` is used when
|vim.net.request| is unavailable.

Optional:
- snacks.nvim       window and history picker
- budoux.lua        Japanese phrase motions (|jisho-budoux|)
- render-markdown.nvim  nicer Markdown rendering

==============================================================================
2. Installation                                         *jisho-installation*

>lua
    vim.pack.add({ 'https://github.com/Imngzx/jisho.nvim' })
    vim.keymap.set({ 'n', 'x' }, '<leader>tj', '<Cmd>Jisho<CR>', { desc = 'Jisho' })
<
That is all: the commands exist right away, and nothing is loaded until the
first lookup. See the README for lazy.nvim and resonance.nvim specs.

==============================================================================
3. Setup                                                       *jisho-setup*

`setup()` is optional. The first lookup, command or history call uses the
defaults; call it only to change something, with only the keys you change:
>lua
    require('jisho').setup({ layout = 'compact' })
<
All options and their defaults:
>lua
    require('jisho').setup({
      use_snacks = pcall(require, 'snacks'),  -- false: native float
      use_budoux = pcall(require, 'budoux'),  -- Budoux phrase motions
      layout = 'spacious',  -- 'compact' | 'spacious' | 'super_spacious'
      timeout = 10000,      -- give up on a request after this many ms
      notify = nil,         -- status style, see |jisho-progress|
      window = {
        width = 0.6,         -- ratio of the editor width
        height = 0.7,        -- ratio of the editor height
        border = 'rounded',  -- any 'winborder' value
      },
    })
<

4. Usage                                                       *jisho-usage*

Commands:                                                  *:Jisho*
    :Jisho [word]           Look up {word}; without one, the selection in
                            Visual mode, else the word under the cursor.
    :'<,'>Jisho             Look up the last selection.
    :{range}Jisho           Look up the text of those lines.
                                                           *:JishoHistory*
    :JishoHistory           Open the search history.
                                                           *:JishoRefresh*
    :JishoRefresh [word]    Look up again, bypassing the cache.
                                                           *:JishoDedupe*
    :JishoDedupe {subcmd}
          inflight          List requests still in flight.
          clear-inflight    Forget in-flight requests.
          clear-cache       Clear the result cache.
          refresh [word]    Same as |:JishoRefresh|.

Lua API:                                                       *jisho-api*
>lua
    require('jisho').search(word)   -- no word: selection in Visual mode,
                                    -- else the word under the cursor
    require('jisho').refresh(word)  -- bypass the cache
    require('jisho').history()
<
`:Jisho` without a word, and `search()` without one, read the selection in
Visual mode and the word under the cursor otherwise, so one mapping serves
both modes (see |jisho-installation|). With a function:
>lua
    vim.keymap.set({ 'n', 'x' }, '<leader>tj', function()
      require('jisho').search()
    end)
<

                                                            *jisho-progress*
While a search runs, its status is shown one of two ways (`notify` option):

`nil` (default)   A spinner notification if a notifier plugin replaced
                  |vim.notify| (snacks.notifier, noice, nvim-notify), else a
                  progress message.
`true`            Spinner notification ("⠋ Searching: 食べる", then
                  "✓ Query successful"), replaced in place via its id.
`false`           One |progress-message| ("Searching: 食べる", then ✓ or ✗),
                  not added to |:messages| unless it fails. Statusline
                  plugins can follow it through the |Progress| event with
                  pattern `jisho`.

The built-in |vim.notify| cannot replace a message, so a spinner there would
add a line to |:messages| for every frame; that is why plain Neovim gets the
progress message.

==============================================================================
5. Result Window                                       *jisho-result-window*

Up to 5 results. Each shows the word with its reading, common and JLPT
tags, other forms, tags, and numbered senses (parts of speech, definitions,
usage notes, see also, sense tags).

    j / k          Next / previous entry or sense
    w / b / e / ge Word motions, by Budoux phrase in Japanese text
    q / <Esc>      Close

                                                              *jisho-budoux*
With budoux.lua installed and `use_budoux` set, `w`, `b`, `e` and `ge` step
through Japanese text one phrase at a time (今日は | 天気が | いいので)
instead of at every change between kanji and kana. Everywhere else they
stop exactly where the built-in motions do. They take a count and work in
Visual mode and after an operator (`yw`, `ye` yank a phrase).

==============================================================================
6. History                                                   *jisho-history*

|:JishoHistory| lists past searches, newest first, with timestamps (max 100).
<CR> searches the entry again. Uses snacks.picker when `use_snacks` is set,
otherwise a floating window (q / <Esc> to close).

==============================================================================
7. Cache and Deduplication                                     *jisho-cache*

Results are cached for 5 minutes, keyed by the trimmed search text, and
saved with the history to `stdpath('cache')/jisho_cache.json`, so they
survive a restart while still fresh.

Searching a word that is already being fetched does not send a second
request: every caller gets the same result.

==============================================================================
8. Layouts                                                   *jisho-layouts*

    compact         No blank lines between blocks
    spacious        One blank line (default)
    super_spacious  Two blank lines

An unknown name falls back to `spacious`.

==============================================================================
9. Events                                                     *jisho-events*

                                                           *JishoWindowOpened*
`User JishoWindowOpened` fires after a result window opens, with
`data = { buf = bufnr, win = winid }`:
>lua
    vim.api.nvim_create_autocmd('User', {
      pattern = 'JishoWindowOpened',
      callback = function(ev) vim.wo[ev.data.win].linebreak = true end,
    })
<
==============================================================================
10. Troubleshooting                                  *jisho-troubleshooting*

Nothing happens       Check |:messages|, your connection, and that `curl`
                      is in PATH if |vim.net.request| is missing.
"Timed out"           Jisho.org did not answer within `timeout`; raise it
                      in |jisho-setup| on a slow connection.
`w` / `e` are plain   budoux.lua not installed or `use_budoux = false`.
Stale result          |:JishoRefresh| {word}.
